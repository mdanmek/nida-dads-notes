# แผนโครงการ DADS5001 Mini Project

อัปเดตล่าสุด: 24 กันยายน 2569

## เป้าหมาย

ใช้ข้อมูล e-GP เพื่อสำรวจรูปแบบของสัญญาจ้างก่อสร้าง และลดสัญญาจำนวนมากให้เหลือ work queue สำหรับเปิดเอกสารตรวจสอบ โดยไม่ตีความ flag ว่าเป็นหลักฐานการทุจริต

## ลำดับการค้นพบ

1. เริ่มจากข้อมูล e-GP 3,964,924 ระเบียน
2. เลือกสัญญาจ้างก่อสร้าง 180,079 สัญญา
3. ตัดรหัสผู้รับจ้างขึ้นต้นด้วย `D` 363 สัญญา เหลือ 179,716 สัญญา
4. สำรวจทั้งหมดก่อนตั้งเกณฑ์ และพบว่าสัญญากระจุกในช่วง 400,000–500,000 บาท โดยวิธีเฉพาะเจาะจงเป็นองค์ประกอบหลัก
5. ขยายดู 400,000–550,000 บาท และเห็นยอดกระจุกทันทีใต้ 500,000 บาท
6. จึงกำหนด Study Scope เป็นงานก่อสร้าง วิธีเฉพาะเจาะจง วงเงินไม่เกิน 500,000 บาท
7. วิเคราะห์ Pattern 1 และ Pattern 2 แยกกัน
8. ใช้จุดตัดของสอง Pattern เป็นรายการตรวจสอบลำดับแรก

## นิยามปัจจุบัน

| หัวข้อ | นิยาม |
|---|---|
| Grain | หนึ่งสัญญา = `รหัสโครงการ + รหัสผู้รับจ้าง + เลขที่สัญญา` |
| Pair grain | `ชื่อหน่วยงาน + รหัส/ชื่อผู้รับจ้าง` |
| Study Scope | งานก่อสร้าง + วิธีเฉพาะเจาะจง + วงเงิน ≤ 500,000 บาท |
| Pattern 1 | คู่เดิมมีสัญญา 490,000–500,000 บาท ≥ 3 สัญญา |
| Pattern 2 | คู่เดิมมีสัญญา ≥ 10 และครองทั้งจำนวนกับมูลค่าในหน่วยงาน ≥ 80% |
| Priority Review | Pattern 1 และ Pattern 2 พร้อมกัน |
| จังหวัด | ใช้เป็นบริบท/เรียงลำดับ ไม่เข้า criteria |
| หน่วยงานย่อย | ตัดออกจาก grain และ criteria |

เกณฑ์ 3, 10 และ 80% เป็น analyst-defined screening thresholds ไม่ใช่เกณฑ์ทางกฎหมาย

## สิ่งที่ต้องตรวจต่อ

- ทำ sensitivity analysis ของเกณฑ์ 3, 10 และ 80%
- ตรวจ TOR ใบเสนอราคา ผู้เสนอราคารายอื่น วันที่จัดซื้อ และขอบเขตงาน
- ตรวจการ normalize ชื่อหน่วยงานและผู้รับจ้าง
- ระวังการตีความ bin ในกราฟใกล้ 500,000 บาท; เมื่อต้องรายงานจำนวนแบบ exact ให้ใช้เงื่อนไข inclusive 490,000–500,000 บาทจากตาราง
- ยืนยันนิยามและหน่วยนับทุกครั้งก่อนนำเสนอ
