## 1. เป้าหมายของการปรับรอบนี้

ปรับ Notebook และ README ให้มีคำถามหลักเพียงเรื่องเดียวและเล่าอย่างต่อเนื่องจากการสำรวจข้อมูลไปสู่การจัดลำดับตรวจสอบ:

```text
ภาพรวมข้อมูลจัดซื้อจัดจ้าง
→ งานจ้างก่อสร้าง
→ พบการกระจุกใกล้ 500,000 บาท
→ เปรียบเทียบวิธีจัดซื้อและพบวิธีเฉพาะเจาะจงมากที่สุด
→ กฎหมายอธิบายการกระจุกเชิงโครงสร้างได้
→ Pattern 1: ตรวจกลุ่มโครงการใกล้เพดานที่เกิดซ้ำกับคู่หน่วยงาน–ผู้รับจ้างเดิม
→ Pattern 2: ตรวจการพึ่งพาผู้รับจ้างรายเดียวสูงภายในหน่วยงานย่อย
→ Pattern 3: ทดสอบการพึ่งพาผู้รับจ้างภายในจังหวัดและไม่พบความสัมพันธ์ตามเกณฑ์
→ ซ้อนทับ Pattern 1 และ Pattern 2
→ เหลือโครงการตรวจสอบลำดับแรก
```

คำถามหลักฉบับปรับใหม่:

> **ภายใต้โครงการจ้างก่อสร้างที่ใช้วิธีเฉพาะเจาะจงและมีวงเงินไม่เกิน 500,000 บาท มีกลุ่มโครงการใกล้เพดานที่เกิดซ้ำกับคู่หน่วยงาน–ผู้รับจ้างเดิมหรือไม่ และกลุ่มเหล่านั้นซ้อนทับกับความสัมพันธ์ที่หน่วยงานพึ่งพาผู้รับจ้างรายเดียวสูงเพียงใด?**

ข้อมูลทุกส่วนต้องระบุว่าเป็น **ข้อมูลปีงบประมาณ 2569 สะสมถึงวันที่ 30 กรกฎาคม 2569 ไม่ใช่ข้อมูลเต็มปี**

## 2. สิ่งที่เปลี่ยนจาก revise06

### 2.1 ตัด Price anomaly ออกจาก Pattern หลัก

ส่วนต่างราคาไม่เชื่อมโดยตรงกับเส้นเรื่องการกระจุกใกล้เพดาน และอาจเกิดจากหลายสัญญา การแก้ไขโครงการ หรือคุณภาพข้อมูล จึงปรับสถานะเป็น:

> **การตรวจคุณภาพข้อมูลและข้อยกเว้นด้านราคา/สัญญา**

ผลส่วนต่างราคา:

- ไม่ใช้เป็น Anomaly Pattern
- ไม่รวมใน Pattern count
- ไม่ใช้จัดลำดับโครงการหลัก
- ไม่อยู่ในเรื่องหลักของ README
- สามารถเก็บตารางตรวจสอบไว้ใน Notebook 04 ภาคคุณภาพข้อมูล โดยไม่ต้องสร้างกราฟสำหรับ README

### 2.2 Pattern หลักเหลือ 2 Pattern

1. กลุ่มโครงการใกล้เพดานที่เกิดซ้ำกับคู่หน่วยงาน–ผู้รับจ้างเดิม
2. การพึ่งพาผู้รับจ้างรายเดียวสูงภายในหน่วยงานย่อย

Pattern 3 ระดับจังหวัดเป็นการทดสอบขอบเขตของสมมติฐาน ไม่รวมในคะแนน เนื่องจากไม่พบคู่จังหวัด–ผู้รับจ้างผ่านเกณฑ์ต่ำสุด 50%

### 2.3 ปรับผลลัพธ์หลัก

ผลลัพธ์หลักไม่ใช่โครงการที่พบอย่างน้อย 2 จาก 3 Pattern อีกต่อไป แต่เป็น intersection โดยตรง:

$$
\mathrm{Priority\ Review}
=\mathrm{Pattern\ 1}\cap\mathrm{Pattern\ 2}
$$

ผลฐานปัจจุบันคือ 291 โครงการ แต่ต้องยืนยันอีกครั้งหลัง Run all

### 2.4 ตัด Future Pattern ที่ไม่ใช้ใน Mini Project

ไม่ทำต่อในรอบนี้:

- Cross-agency supplier
- Temporal burst
- Similar project names
- Location continuity
- Multiple-contract pattern
- Repeated standardized amount

เหตุผลคืออยู่นอกคำถามหลัก ต้องใช้ข้อมูลเพิ่มเติม ซ้อนกับ Pattern ปัจจุบัน หรือสามารถเปลี่ยนรูปแบบเพื่อหลีกเลี่ยงกฎคัดกรองได้ง่าย

## 5. Notebook 03 — Construction EDA และบริบทกฎหมาย

ไฟล์: `03_construction_eda_2569.ipynb`

### 5.1 สำรวจขนาดโครงการโดยยังไม่อ้างกฎหมาย

เริ่มจาก 178,978 โครงการและสำรวจ:

- Distribution ของวงเงิน
- Median และ mean
- Budget band
- สัดส่วนจำนวนโครงการเทียบวงเงินรวม
- วงเงินที่ปรากฏบ่อย

คำถาม:

> โครงการก่อสร้างส่วนใหญ่อยู่ช่วงใด และมีจุดกระจุกบริเวณใด?

ผลต้องนำไปสู่การค้นพบว่าจำนวนโครงการกระจุกบริเวณ 500,000 บาท โดยยังไม่ใช้กฎหมายเป็นจุดเริ่มต้น

### 5.2 เปรียบเทียบวิธีจัดซื้อ

หลังพบการกระจุกจึงถาม:

> การกระจุกใกล้ 500,000 บาทสัมพันธ์กับวิธีจัดซื้อใด?

เปรียบเทียบอย่างน้อย:

- วิธีเฉพาะเจาะจง
- e-bidding
- วิธีคัดเลือก

แสดงทั้งสัดส่วนจำนวนโครงการและสัดส่วนวงเงินรวม เพื่อแยกความหมายระหว่าง “วิธีที่ใช้บ่อย” กับ “วิธีที่ครองมูลค่า”

### 5.3 ใช้กฎหมายอธิบายสิ่งที่พบ

อธิบายหลังเห็นผลจากข้อมูลแล้ว:

- มาตรา 55: วิธีจัดซื้อจัดจ้างหลัก
- มาตรา 56 วรรคหนึ่ง (2)(ข): เงื่อนไขการใช้วิธีเฉพาะเจาะจง
- กฎกระทรวง: วงเงินไม่เกิน 500,000 บาท

ข้อสรุป:

> การกระจุกของวิธีเฉพาะเจาะจงใต้ 500,000 บาทเป็น expected structural pattern ที่กฎหมายอธิบายได้ จึงไม่ใช่ anomaly ด้วยตัวเอง

### 5.4 กำหนดกลุ่มศึกษาหลัก

```text
178,978 โครงการก่อสร้างทั้งหมด
→ 136,623 โครงการวงเงินไม่เกิน 500,000 บาท
→ 136,070 โครงการวิธีเฉพาะเจาะจงและวงเงินไม่เกิน 500,000 บาท
```

### 5.5 จุดจบของ Notebook 03

จบด้วยคำถามส่งต่อ:

> แม้กฎหมายจะอธิบายได้ว่าเหตุใดโครงการจึงกระจุกใต้ 500,000 บาท แต่กฎหมายยังไม่อธิบายว่าเหตุใดบางหน่วยงานจึงมีหลายโครงการใกล้เพดานกับผู้รับจ้างเดิม และเหตุใดบางหน่วยงานจึงพึ่งพาผู้รับจ้างรายเดียวสูง

EDA เสริม เช่น อันดับหน่วยงาน Supplier Pareto และการตรวจราคา สามารถเก็บในส่วนท้ายของ Notebook แต่ไม่อยู่ในเรื่องหลักและไม่ใช้ใน README

## 6. Notebook 04 — Pattern Detection

ไฟล์: `04_construction_review_indicators_2569.ipynb`

### 6.1 ส่วนเตรียมก่อนตรวจ Pattern

ตรวจ reconciliation ที่จำเป็น:

- หนึ่งแถวต่อโครงการสำหรับ Pattern flag
- การจัดการ Joint Venture
- หนึ่ง entity ต่อผู้รับจ้างหรือกลุ่มผู้รับจ้าง
- ความครบถ้วนของหน่วยงานย่อย ผู้รับจ้าง วันที่ และจังหวัด
- ยอดรวมระดับโครงการกับระดับสัญญา

ข้อยกเว้นด้านราคาและหลายสัญญาให้อยู่ในส่วน Data-quality appendix ไม่เรียกว่า Pattern และไม่ส่งผลต่อ priority

### 6.2 Pattern 1 — กลุ่มโครงการใกล้เพดานที่เกิดซ้ำกับคู่หน่วยงาน–ผู้รับจ้างเดิม

ชื่อเต็มที่ใช้ใน Markdown และ README:

> **กลุ่มโครงการใกล้เพดานที่บันทึกในวันเดียวกันกับคู่หน่วยงาน–ผู้รับจ้างเดิม**

ใช้คำว่า “วันที่เกิดรายการ” ในคำอธิบาย เพราะข้อมูลไม่มีวันที่ประกาศสำหรับโครงการเฉพาะเจาะจง

เงื่อนไขหลัก:

- อยู่ในกลุ่มศึกษาหลัก
- วงเงิน 490,000–500,000 บาท
- หน่วยงานย่อยเดียวกัน
- ผู้รับจ้างเดียวกัน
- วันที่เกิดรายการเดียวกัน
- อย่างน้อย 3 โครงการ

Sensitivity ที่ต้องเก็บ:

- หน้าต่าง 450–500k, 480–500k, 490–500k และ 495–500k
- จำนวนขั้นต่ำ 2, 3, 5 และ 10 โครงการ

ผลฐานปัจจุบัน:

- 1,245 กลุ่ม
- 5,623 โครงการ

### 6.3 Pattern 2 — การพึ่งพาผู้รับจ้างรายเดียวสูงภายในหน่วยงานย่อย

เงื่อนไขหลัก:

- ผู้รับจ้างได้รับอย่างน้อย 10 โครงการ
- ครองอย่างน้อย 75% ของจำนวนโครงการในหน่วยงานย่อย
- ครองอย่างน้อย 75% ของมูลค่าในหน่วยงานย่อย

Sensitivity ที่ต้องเก็บ:

- จำนวนงานขั้นต่ำ 5, 10 และ 20 โครงการ
- ส่วนแบ่ง 50%, 75% และ 90%

ผลฐานปัจจุบัน:

- 142 คู่หน่วยงานย่อย–ผู้รับจ้าง
- ผู้รับจ้าง 130 ราย
- 2,421 โครงการ

### 6.4 Pattern 3 — การพึ่งพาผู้รับจ้างภายในจังหวัด

Pattern 3 เป็นการทดสอบขอบเขต ไม่ใช่คะแนนหลัก

คำถาม:

> เมื่อขยาย denominator จากหน่วยงานย่อยเป็นทั้งจังหวัด ยังมีผู้รับจ้างรายใดครองทั้งจำนวนและมูลค่างานสูงหรือไม่?

เกณฑ์ทดลอง:

- จังหวัดมีอย่างน้อย 20, 50 หรือ 100 โครงการ
- ผู้รับจ้างได้รับอย่างน้อย 5, 10 หรือ 20 โครงการ
- ส่วนแบ่ง 50%, 75% หรือ 90% ทั้งจำนวนและมูลค่า

ผลฐานปัจจุบัน:

- ไม่พบคู่จังหวัด–ผู้รับจ้างผ่านแม้แต่เกณฑ์ 50%
- ส่วนแบ่งสูงสุดอยู่ประมาณ 14–15%

ข้อสรุปที่ต้องใช้:

> Pattern การพึ่งพาผู้รับจ้างปรากฏในระดับหน่วยงานย่อย แต่ไม่ขยายเป็นการครองงานทั้งจังหวัดภายใต้เกณฑ์ที่ทดลอง

Pattern 3 ไม่สร้าง project flag สำหรับ priority และไม่รวมกับ Pattern 1–2

### 6.5 การซ้อนทับ Pattern 1 และ Pattern 2

ใช้ intersection โดยตรง:

```text
Pattern 1: 5,623 โครงการ
Pattern 2: 2,421 โครงการ
Pattern 1 ∩ Pattern 2: 291 โครงการ
```

กลุ่มตรวจสอบลำดับแรกคือโครงการที่พบทั้งสอง Pattern เท่านั้น

ค่าที่คาดหลังตัด Price anomaly ออกจากคะแนน:

| กลุ่ม | จำนวนที่คาดจากผลปัจจุบัน |
|---|---:|
| ไม่พบ Pattern 1 หรือ 2 | 128,317 |
| พบเพียง Pattern เดียว | 7,462 |
| พบทั้ง Pattern 1 และ 2 | 291 |
| พบอย่างน้อยหนึ่ง Pattern | 7,753 |

ตัวเลขข้างต้นเป็นค่าคำนวณจาก baseline เดิม ต้องยืนยันจาก Output หลัง Run all

## 7. มาตรฐาน Visual Design

เป้าหมายคือกราฟแบบ **minimal, modern, formal** ที่อ่านและตีความได้ทันทีในระดับงาน Data Analyst มืออาชีพ

### 7.1 หลักการออกแบบ

- หนึ่งกราฟตอบคำถามหลักเพียงหนึ่งข้อ
- ชื่อกราฟต้องเป็น takeaway หรือคำถามที่กราฟตอบ ไม่ใช้เพียงชื่อคอลัมน์
- ใช้พื้นหลังสีขาว ไม่มีกรอบรอบกราฟ
- ใช้เส้น grid เฉพาะที่ช่วยอ่านค่า และใช้สีเทาอ่อน
- หลีกเลี่ยง 3D, pie chart หลายส่วน, dual axis และองค์ประกอบตกแต่งที่ไม่เพิ่มความหมาย
- เรียง bar ตามค่า เว้นแต่ลำดับช่วงหรือลำดับกระบวนการมีความหมาย
- หมวดหมู่ตั้งแต่ 6 รายการขึ้นไปใช้ horizontal bar เพื่ออ่าน label ได้ครบ
- แสดง direct label เมื่อช่วยลดการกวาดสายตา และตัด legend เมื่อ label บนกราฟเพียงพอ

## 9. Specification ของ Visual แต่ละรูป

### รูป 2 — Budget band: count vs value

- Title เป็นข้อค้นพบ ไม่ใช้คำว่า anomaly

## 15. ข้อสรุปที่ Project ต้องตอบได้

> การกระจุกของโครงการวิธีเฉพาะเจาะจงใต้ 500,000 บาทมีคำอธิบายจากกฎหมาย จึงไม่ใช่ anomaly ด้วยตัวเอง แต่ภายในกลุ่มที่อยู่ภายใต้เงื่อนไขเดียวกัน พบกลุ่มโครงการใกล้เพดานที่บันทึกในวันเดียวกันกับคู่หน่วยงาน–ผู้รับจ้างเดิม และบางคู่มีการพึ่งพาผู้รับจ้างรายเดียวสูงทั้งจำนวนและมูลค่า เมื่อซ้อนทับสอง Pattern เหลือ 291 โครงการสำหรับเปิดเอกสารตรวจสอบลำดับแรก ขณะที่การทดสอบระดับจังหวัดไม่พบการครองงานตามเกณฑ์ที่ทดลอง แสดงว่า Pattern เด่นเกิดในระดับความสัมพันธ์เฉพาะของหน่วยงานย่อย ไม่ใช่ทั่วทั้งจังหวัด

ผลลัพธ์นี้ใช้จัดลำดับการตรวจเอกสาร ไม่ใช้ตัดสินเจตนา ความผิด หรือการทุจริต
