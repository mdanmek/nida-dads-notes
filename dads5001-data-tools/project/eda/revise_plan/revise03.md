## เป้าหมาย

ปรับ Visual ให้ทุกภาพมีหน้าที่ในเรื่องเล่า ตั้งแต่เห็นรูปแบบข้อมูล ไปจนถึงสร้างตัวชี้วัดและลดจำนวนโครงการสำหรับตรวจสอบ ภาพที่ไม่เชื่อมกับคำถาม ตัวชี้วัด หรือข้อสรุปจะเก็บไว้ใน Notebook หรือภาคผนวก แต่ไม่นำเสนอใน README หลัก

ขอบเขตข้อมูลต้องเขียนว่า **ข้อมูลปีงบประมาณ 2569 สะสมถึงวันที่ 30 กรกฎาคม 2569** ไม่ใช่ข้อมูลเต็มปี

คำถามกลางคือ:

> ในโครงการจ้างก่อสร้าง 178,978 โครงการ มีรูปแบบใดที่ช่วยลดขอบเขตและจัดลำดับโครงการสำหรับเปิดเอกสารตรวจสอบก่อน?


## 0. ที่มา ความสำคัญ และชื่อโครงการ

เรื่องเล่าต้องเริ่มจากปัญหาการตัดสินใจ ไม่ใช่เริ่มจากการพบโครงการใกล้ 500,000 บาท:

> ข้อมูลจัดซื้อจัดจ้างภาครัฐมีโครงการจำนวนมาก แต่ทรัพยากรสำหรับตรวจเอกสารมีจำกัด เราจะใช้ข้อมูล e-GP ที่เปิดเผยต่อสาธารณะช่วยจัดลำดับว่าโครงการใดควรได้รับการตรวจสอบก่อนอย่างเป็นระบบได้หรือไม่

ความสำคัญของโครงการมี 3 ระดับ:

1. เปลี่ยนข้อมูลหลายล้านรายการให้เป็นข้อมูลที่ใช้ตัดสินใจได้
2. ลดภาระจากการเปิดเอกสารทุกโครงการ
3. สร้างเกณฑ์คัดกรองที่โปร่งใส อธิบายได้ และทำซ้ำได้ แทนการเลือกจากความรู้สึก

ชื่อโครงการที่เสนอ:

> **การใช้ข้อมูล e-GP เพื่อจัดลำดับการตรวจสอบโครงการจ้างก่อสร้าง: กรณีศึกษาปีงบประมาณ 2569 ณ วันที่ 30 กรกฎาคม 2569**

ผลจากการเป็นข้อมูลระหว่างปี:

- ห้ามเรียกว่า “ข้อมูลตลอดปี 2569”
- จำนวนและมูลค่าทั้งหมดเป็นข้อมูลสะสมระหว่างปี
- ไม่เปรียบเทียบโดยตรงกับข้อมูลเต็มปีของปีอื่น
- รูปแบบและจำนวนโครงการอาจเปลี่ยนเมื่อมีข้อมูลเดือนสิงหาคม–กันยายนเพิ่ม

## 3. การเปรียบเทียบราคา 3 มิติ

**ควรเทียบทั้ง 3 มิติ** เพราะมีบทบาทต่างกัน:

| ตัวแปร | ความหมาย |
|---|---|
| วงเงินงบประมาณ | กรอบทรัพยากรของโครงการ |
| ราคากลาง | ราคาอ้างอิง |
| ราคาที่ตกลง | ผลลัพธ์ราคาที่เกิดขึ้นจริง |

ไม่ใช้กราฟ 3 มิติ เพราะอ่านระยะและตำแหน่งยากบน README ให้สร้างภาพ normalized สอง panel:

### Panel A — Three-price relationship

- แกน X = ราคากลาง / วงเงินงบประมาณ
- แกน Y = ราคาที่ตกลง / วงเงินงบประมาณ
- เส้นตั้ง x = 1: ราคากลางเท่ากับงบประมาณ
- เส้นนอน y = 1: ราคาตกลงเท่ากับงบประมาณ
- เส้นทแยง y = x: ราคาตกลงเท่ากับราคากลาง
- ใช้ hexbin หรือ scatter โปร่งใสเพื่อลดปัญหาจุดทับกัน

การอ่านภาพ:

- เหนือเส้นนอน = ราคาตกลงสูงกว่างบประมาณ
- เหนือเส้นทแยง = ราคาตกลงสูงกว่าราคากลาง
- ห่างจากเส้นตั้ง = ราคากลางต่างจากงบประมาณมาก

### Panel B — Material price-review status

แสดงจำนวนโครงการ 4 กลุ่ม:

1. ไม่เข้าเกณฑ์
2. สูงกว่างบประมาณอย่างเดียว
3. สูงกว่าราคากลางอย่างเดียว
4. สูงกว่าทั้งงบประมาณและราคากลาง

ใช้เกณฑ์เดียวกับ Notebook 04 คือ ส่วนต่างมากกว่า 10,000 บาท **และ** มากกว่า 1%

ข้อกำหนด:

- ใช้เฉพาะแถวที่งบประมาณมากกว่าศูนย์
- การเทียบราคากลางใช้เฉพาะราคากลางที่ผ่านเกณฑ์คุณภาพ
- ระบุจำนวนแถวที่ไม่ถูกใช้ในกราฟ
- หากสุ่มจุด ใช้ random_state=42 และคำนวณสถิติจากข้อมูลทั้งหมด
- แยก “ข้อมูลผิดสังเกต” ออกจาก “ตัวชี้วัดเพื่อการตรวจสอบ”

ชื่อไฟล์เสนอ: **figure/fig03_03_three_price_relationship.png**

## 4. Visual ที่ควรเพิ่ม

### 4.1 จุดกระจุกตัวใกล้ 500,000 บาทตามวิธีจัดซื้อ

กราฟช่วงงบเดิมยังกว้างเกินไป ควรเพิ่ม histogram หรือ bar ช่วง 450,000–500,000 บาท แยกตามวิธีจัดซื้อ โดยใช้ bin 1,000 หรือ 5,000 บาท เพื่อให้เห็นว่า:

- จุดกระจุกตัวเกิดกับวิธีเฉพาะเจาะจงเป็นหลักหรือไม่
- เหตุใดจึงเลือกช่วง 490,000–500,000 บาท

### 4.2 การกระจุกตัวระดับหน่วยงานย่อย–ผู้รับจ้าง

เพิ่ม scatter plot:

- แกน X = สัดส่วนจำนวนโครงการที่ผู้รับจ้างได้รับในหน่วยงานย่อย

| ราคา 3 มิติ | ราคาตกลงสัมพันธ์กับงบประมาณและราคากลางอย่างไร | สร้างตัวชี้วัดส่วนต่างราคา | เรื่องหลัก |
| อันดับหน่วยงานและจังหวัด | ใครหรือพื้นที่ใดมีจำนวน/มูลค่าสูง | ปัจจุบันไม่ได้ใช้สร้างตัวชี้วัด | ตัดจาก README หรือภาคผนวก |
| Supplier Pareto | ระดับประเทศกระจุกตัวเพียงใด | ตั้งคำถามต่อในระดับหน่วยงานย่อย | เก็บสั้นมากหรือภาคผนวก |
| Joint Venture (JV) | เหตุใดยอดระดับสัญญาถูกนับซ้ำ | แก้ grain และคุณภาพข้อมูล | คำอธิบายสั้น |
| Threshold sensitivity ของราคา | จำนวน flag เปลี่ยนอย่างไรเมื่อเปลี่ยนเกณฑ์ | รองรับเหตุผลของเกณฑ์ 10,000 บาทและ 1% | เพิ่มในเรื่องหลักเป็นตารางหรือภาพขนาดเล็ก |
| Cluster ใกล้ 500,000 บาท | โครงการลักษณะเดียวกันเกิดซ้ำหรือไม่ | สร้าง repeated-pattern indicator | เรื่องหลัก |
| Concentration ระดับหน่วยงานย่อย | ผู้รับจ้างรายเดียวครองงานสูงหรือไม่ | สร้าง concentration indicator | เรื่องหลัก |

## 10. การอธิบาย Joint Venture (JV)

ครั้งแรกให้เขียนว่า:

> กลุ่มผู้รับจ้างแบบ **Joint Venture (JV)** คือการที่ผู้ประกอบการหลายรายร่วมกันรับงานภายใต้โครงการหรือสัญญาเดียวกัน

จากนั้นใช้คำว่า Joint Venture (JV) ตลอด ไม่ใช้คำว่า Consortium สลับกันโดยไม่มีคำอธิบาย

อธิบายปัญหาการนับข้อมูลว่า:

> บางโครงการมีทั้งแถวของ Joint Venture ซึ่งบันทึกมูลค่าสัญญาทั้งก้อน และแถวของบริษัทสมาชิกซึ่งบันทึกส่วนแบ่งของแต่ละราย หากรวมทุกแถวจะทำให้มูลค่าถูกนับซ้ำ

ใน README ไม่จำเป็นต้องใช้คำว่า Supplier Entity บ่อย ให้เขียนว่า:

> หลังไม่นับแถวสมาชิก JV ซ้ำ พบผู้รับจ้างหรือกลุ่มผู้รับจ้างที่ใช้วิเคราะห์ 33,570 ราย

## 11. กรวยคำถามของโครงการ

### คำถามตั้งต้น

> ข้อมูล e-GP สามารถช่วยจัดลำดับโครงการจ้างก่อสร้างที่ควรเปิดเอกสารตรวจสอบก่อนได้หรือไม่

### ขั้นที่ 1 — ทำความเข้าใจ Grain

> หนึ่งแถวหมายถึงโครงการ สัญญา หรือผู้รับจ้าง และต้องเตรียมข้อมูลอย่างไรก่อนวิเคราะห์?

คำตอบ: 180,079 แถวถูกจัดเป็น 178,978 โครงการ และต้องจัดการแถวสมาชิก JV เพื่อไม่ให้นับมูลค่าซ้ำ

### ขั้นที่ 2 — หาโครงสร้างพื้นฐาน

> โครงการส่วนใหญ่มีขนาดเท่าใด และใช้วิธีจัดซื้อใด?

คำตอบ: 76.34% มีงบไม่เกิน 500,000 บาท และวิธีเฉพาะเจาะจงมีจำนวนมากที่สุด

### ขั้นที่ 3 — แยกรูปแบบทั่วไปออกจากรูปแบบที่ควรตรวจ

> การอยู่ใกล้ 500,000 บาทเพียงอย่างเดียวเพียงพอเป็นตัวชี้วัดหรือไม่?

คำตอบ: ไม่เพียงพอ เพราะความสัมพันธ์ระหว่างวงเงินระดับนี้กับวิธีเฉพาะเจาะจงอาจเป็นรูปแบบที่คาดหมายจากกรอบการจัดซื้อจัดจ้าง จึงห้ามใช้ “ใกล้ 500,000 บาท” เป็นตัวชี้วัดเดี่ยว

ก่อนเขียนข้อกฎหมายใน README ต้องตรวจสอบและอ้างอิงกฎกระทรวงหรือแนวทางจัดซื้อจัดจ้างจากแหล่งราชการที่ระบุประเภทเอกสาร วันที่ และข้อกำหนดอย่างชัดเจน ไม่ใช่อ้างเพียงหน้าแรกของเว็บไซต์

คำถามถัดไปคือ:

> โครงการเฉพาะเจาะจงใกล้ 500,000 บาทเกิดซ้ำภายใต้หน่วยงานย่อย ผู้รับจ้าง และวันเดียวกันหรือไม่?

### ขั้นที่ 4 — ตรวจผู้รับจ้าง

> กลุ่มโครงการที่เกิดซ้ำสัมพันธ์กับผู้รับจ้างที่ครองทั้งจำนวนและมูลค่าในหน่วยงานย่อยสูงหรือไม่?

คำตอบ: พบการซ้อนทับ 102 โครงการ

### ขั้นที่ 5 — ตรวจราคาเป็นมิติประกอบ

> มีโครงการที่ราคาตกลงสูงกว่างบประมาณหรือราคากลางอย่างมีสาระสำคัญหรือไม่?

คำตอบ: พบ 406 โครงการ แต่มีเพียง 1 โครงการที่ซ้อนทับกับ repeated near-500K และไม่ซ้อนทับกับ concentration ดังนั้นมิติราคาเป็นประเด็นรองของเรื่องหลัก แต่ยังมีประโยชน์สำหรับคัดกรองอีกเส้นทางหนึ่ง

### ขั้นที่ 6 — จัดลำดับ

> เมื่อใช้หลายมิติร่วมกัน เหลือโครงการที่ควรตรวจสอบก่อนกี่โครงการ?

คำตอบ: 103 โครงการ

กรวยเชิงตัวเลข:

```text
178,978 โครงการ
→ 26,154 โครงการเฉพาะเจาะจงช่วง 490K–500K
→ 5,623 โครงการที่เกิดซ้ำเป็นกลุ่ม
→ ตรวจการกระจุกตัวของผู้รับจ้างและมิติราคา
→ 103 โครงการที่พบอย่างน้อย 2 มิติ
```

หมายเหตุ: ขั้น “โครงการขนาดเล็กและวิธีเฉพาะเจาะจง” ใช้อธิบายบริบท แต่ไม่ใช่จำนวน flag และไม่ควรวาดใน Funnel ให้เหมือนเป็นการตัดสินความเสี่ยงแล้ว

## 12. คำตอบและ Insight ที่ต้องปรากฏท้าย README

### สิ่งที่ตอบได้

> ข้อมูล e-GP สามารถใช้สร้างกระบวนการจัดลำดับการตรวจสอบที่โปร่งใสและทำซ้ำได้ โดยลดขอบเขตจาก 178,978 โครงการ เหลือ 103 โครงการที่พบรูปแบบซ้อนทับอย่างน้อย 2 มิติและควรเปิดเอกสารตรวจสอบก่อน

### Insight หลัก

ประเด็นสำคัญไม่ใช่เพียง “มีโครงการจำนวนมากใกล้ 500,000 บาท” แต่คือ:

> ในโครงการเฉพาะเจาะจงช่วง 490,000–500,000 บาท พบ 5,623 โครงการที่เกิดซ้ำภายใต้หน่วยงานย่อย ผู้รับจ้าง และวันเดียวกัน และใน High priority 103 โครงการ มี 102 โครงการที่ซ้อนทับกับการกระจุกตัวสูงของผู้รับจ้างภายในหน่วยงานย่อย

ดังนั้นแก่นของเรื่องคือ:

> **โครงการใกล้ 500,000 บาทเกิดซ้ำในรูปแบบเดียวกัน และสัมพันธ์กับผู้รับจ้างที่ครองงานของหน่วยงานย่อยหรือไม่**

ตัวชี้วัดราคาเป็นเรื่องรองของเส้นเรื่องหลัก เพราะจาก 406 โครงการที่พบส่วนต่างราคา มีเพียง 1 โครงการที่เข้าสู่ High priority จากการซ้อนทับกับตัวชี้วัดอื่น

### สิ่งที่ยังตอบไม่ได้

ข้อมูลนี้ยังตอบไม่ได้ว่า:

- เหตุใดจึงแยกโครงการ
- การแข่งขันเพียงพอหรือไม่
- มีการกระทำผิดหรือไม่

ต้องตรวจแผนจัดซื้อ ขอบเขตงาน เอกสารอนุมัติ การแก้ไขสัญญา และข้อมูลผู้เสนอราคารายอื่นก่อนสรุปสาเหตุ
