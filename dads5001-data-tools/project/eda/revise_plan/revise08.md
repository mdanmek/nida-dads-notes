## 1. เป้าหมายของการปรับรอบนี้

ปรับ Notebook 02–04 ให้ใช้ grain คอลัมน์มูลค่า และลำดับชั้นหน่วยงานในความหมายเดียวกันตลอดทั้งโครงการ ก่อน Run all และรีวิว output รอบถัดไป

1. ใช้คีย์ข้อมูลไม่ซ้ำตามที่กำหนด
2. ใช้คอลัมน์มูลค่าเดียวกันทุก Notebook
3. รักษาลำดับชั้น `ชื่อหน่วยงาน → ชื่อหน่วยงานย่อย`

5. เพิ่ม `shape` และ `head()` หลังอ่านข้อมูลใน Notebook 03 และ 04
6. ทำ visual style ให้สอดคล้องกัน
7. ตัด code และ Markdown ที่ไม่จำเป็น
8. Run all แล้วจึงพิจารณาผลและแก้ README ในรอบถัดไป

รอบนี้ยังไม่กำหนดจำนวนโครงการที่ควรได้ เพราะตัวเลขเดิมเกิดจากการใช้คอลัมน์มูลค่าไม่ตรงกัน ผลทั้งหมดต้องคำนวณใหม่

## 2. ข้อตกลงข้อมูลที่ใช้ร่วมกัน

### 2.1 Grain ของข้อมูลรายการ

หนึ่งรายการไม่ซ้ำกำหนดด้วย:

```python
unique_key = [
    'รหัสโครงการ',
    'เลขประจำตัวนิติบุคคล 13 หลัก',
    'เลขที่สัญญา'
]
```

ลำดับการเตรียมข้อมูล:

1. เลือกเฉพาะประเภทโครงการ `จ้างก่อสร้าง`
2. ตัดรหัสผู้รับจ้างที่ขึ้นต้นด้วย `D`
3. ตัดแถวซ้ำด้วย `unique_key`
4. เก็บหลายสัญญาภายในโครงการเดิมไว้
5. เก็บผู้รับจ้างหลายรายภายในโครงการเดิมไว้

### 2.2 คอลัมน์มูลค่า

ใช้คอลัมน์นี้เป็นมูลค่าหลักตลอด Notebook 02–04:

```python
contract_value_column = 'วงเงินงบประมาณในสัญญา (บาท)'
```

ไม่ใช้สองคอลัมน์ต่อไปนี้ในการคำนวณมูลค่า การแบ่งช่วงวงเงิน หรือสัดส่วนมูลค่า:

```text
วงเงินงบประมาณ (บาท)
ราคาที่ตกลงซื้อ / จ้าง ซึ่งรวมทุกสัญญาในโครงการ (บาท)
```

คอลัมน์ดังกล่าวยังเก็บไว้เป็นข้อมูลประกอบได้ แต่ต้องไม่ถูกใช้แทน `วงเงินงบประมาณในสัญญา (บาท)`

### 2.3 คอลัมน์ตามวัตถุประสงค์

| วัตถุประสงค์ | คอลัมน์ |
|---|---|
| ระบุโครงการ | `รหัสโครงการ` |
| ระบุผู้รับจ้าง | `เลขประจำตัวนิติบุคคล 13 หลัก` |
| ระบุสัญญา | `เลขที่สัญญา` |
| มูลค่า | `วงเงินงบประมาณในสัญญา (บาท)` |
| วิธีจัดซื้อ | `ชื่อวิธีการจัดซื้อจัดจ้าง` |
| จังหวัด | `จังหวัด` |
| หน่วยงาน | `ชื่อหน่วยงาน` |
| หน่วยงานย่อย | `ชื่อหน่วยงานย่อย` |

### 2.4 ลำดับชั้นหน่วยงาน

`ชื่อหน่วยงานย่อย` เป็น subset ของ `ชื่อหน่วยงาน` ดังนั้นการวิเคราะห์ระดับหน่วยงานย่อยต้องใช้สองคอลัมน์ร่วมกัน:

```python
[
    'ชื่อหน่วยงาน',
    'ชื่อหน่วยงานย่อย'
]
```

ห้ามจัดกลุ่มด้วย `ชื่อหน่วยงานย่อย` เพียงคอลัมน์เดียว เพราะชื่อเดียวกันอาจปรากฏภายใต้คนละหน่วยงาน

### 5.2 การวิเคราะห์มูลค่า

### 6.2 Pattern 1 — โครงการใกล้เพดานที่เกิดซ้ำ

ใช้มูลค่าที่มาจาก `วงเงินงบประมาณในสัญญา (บาท)`

เงื่อนไข:

- วิธีเฉพาะเจาะจง
- มูลค่าไม่เกิน 500,000 บาท
- อยู่ในช่วง 490,000–500,000 บาท
- คู่ `ชื่อหน่วยงาน + ชื่อหน่วยงานย่อย + ผู้รับจ้าง` เดียวกัน
- อย่างน้อย 3 รหัสโครงการไม่ซ้ำ
- ไม่ใช้วันที่เกิดรายการเป็นเงื่อนไข

คอลัมน์จัดกลุ่ม:

```python
[
    'ชื่อหน่วยงาน',
    'ชื่อหน่วยงานย่อย',
    'เลขประจำตัวนิติบุคคล 13 หลัก'
]
```

### 6.3 Pattern 2 — การพึ่งพาผู้รับจ้างในชื่อหน่วยงาน

จัดกลุ่มด้วย:

```python
[
    'ชื่อหน่วยงาน',
    'เลขประจำตัวนิติบุคคล 13 หลัก'
]
```

เกณฑ์:

- ผู้รับจ้างได้รับอย่างน้อย 10 รหัสโครงการไม่ซ้ำ
- สัดส่วนจำนวนโครงการอย่างน้อย 75%
- สัดส่วนวงเงินสัญญาอย่างน้อย 75%

ทั้งตัวตั้งและตัวหารของสัดส่วนวงเงินต้องมาจาก:

```text
วงเงินงบประมาณในสัญญา (บาท)
```

### 6.4 Pattern 3 — การพึ่งพาผู้รับจ้างในชื่อหน่วยงานย่อย

จัดกลุ่มด้วย:

```python
[
    'ชื่อหน่วยงาน',
    'ชื่อหน่วยงานย่อย',
    'เลขประจำตัวนิติบุคคล 13 หลัก'
]
```

ตัวหารต้องคำนวณภายในคู่:

```python
[
    'ชื่อหน่วยงาน',
    'ชื่อหน่วยงานย่อย'
]
```

ใช้เกณฑ์จำนวนโครงการและสัดส่วนเดียวกับ Pattern 2

### 6.5 Pattern 4 — การพึ่งพาผู้รับจ้างในจังหวัด

จัดกลุ่มด้วย:

```python
[
    'จังหวัด',
    'เลขประจำตัวนิติบุคคล 13 หลัก'
]
```

เกณฑ์:

- จังหวัดมีอย่างน้อย 20 รหัสโครงการไม่ซ้ำ
- ผู้รับจ้างได้รับอย่างน้อย 5 รหัสโครงการไม่ซ้ำ
- สัดส่วนจำนวนโครงการอย่างน้อย 50%
- สัดส่วนวงเงินสัญญาอย่างน้อย 50%

ทั้งตัวตั้งและตัวหารใช้ `วงเงินงบประมาณในสัญญา (บาท)`

### 6.6 การจัดลำดับตรวจสอบ

เกณฑ์ยังคงเป็น:

```text
Pattern 1 และ (Pattern 2 หรือ Pattern 3)
```

Pattern 4 ใช้เป็นบริบทระดับจังหวัด ไม่รวมใน priority

จำนวนโครงการทั้งหมดต้องนับด้วย `รหัสโครงการ` แบบไม่ซ้ำ ส่วนไฟล์รายละเอียดสามารถมีหลายแถวต่อโครงการเมื่อโครงการเดียวผ่านมากกว่าหนึ่งระดับ

## 8. Markdown และการเล่าเรื่อง

- ไม่บรรยายผลก่อนรัน cell
- ไม่กล่าวล่วงหน้าว่าจะพบ Pattern หรือได้จำนวนเท่าใด
- Markdown ก่อน code บอกเฉพาะคำถามหรือสิ่งที่จะคำนวณ
- Markdown หลัง output อธิบายเฉพาะสิ่งที่เห็นจาก output
- ไม่กล่าวถึง Notebook ถัดไปก่อนถึงส่วนสรุป
- ไม่ใส่ตัวเลขจาก output เป็นข้อความคงที่ หาก code อาจเปลี่ยนผล
- ไม่เรียกโครงการว่า fraud หรือทุจริต
- ใช้คำว่า “โครงการตรวจสอบลำดับแรก”
- อธิบายว่าตารางแต่ละแถวแทน grain ใด

README จะปรับหลัง Run all และยืนยัน output ใหม่แล้วเท่านั้น

## 9. Code style

- ใช้ single quotes
- ใช้ pandas, NumPy, Matplotlib และ Seaborn ในระดับพื้นฐาน
- ไม่สร้าง class
- ไม่ใช้โครงสร้าง abstraction ซับซ้อน
- ใช้ function เฉพาะส่วนที่คำนวณซ้ำชัดเจนและช่วยลด code จริง
- ไม่ใช้ assert
- ไม่ตรวจ JV ซ้ำหลัง Notebook 02
- ไม่ตัด duplicate ซ้ำใน Notebook 03–04
- ไม่ทำ reconciliation ที่ไม่จำเป็น
- ไม่เก็บตัวแปรที่ไม่ได้ใช้
- ไม่สร้างตาราง intermediate หากไม่ถูกใช้ใน output หรือขั้นถัดไป
- หนึ่ง cell ทำหน้าที่หลักหนึ่งเรื่อง
